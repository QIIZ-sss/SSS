# วาดต่อ — เกมวาดรูปส่งต่อกัน

วาดตามคำใบ้ → เพื่อนดูภาพสิบวินาทีแล้วทายว่าเป็นภาพอะไร → คนถัดไปวาดตามคำตอบนั้นโดยไม่เห็นภาพเดิม → วนไปเรื่อย ๆ
ตอนจบเปิดดูพร้อมกันว่าคำใบ้ตั้งต้นเดินทางผ่านมือทุกคนแล้วกลายเป็นอะไร

ระหว่างทางมี "ของแถม" สุ่มมาป่วน เช่น ห้ามยกมือ หรือยางลบผีที่ลบภาพไปเองบางส่วนก่อนส่งให้คนทาย

### กติกาโดยละเอียด

| รอบ | ประเภท | ผู้เล่นเห็นอะไร | ทำอะไร |
|---|---|---|---|
| 0 | วาด | คำใบ้ของระบบ | วาดบนกระดาษเปล่า |
| 1 | ทาย | ภาพของคนอื่น (ดูได้ 10 วิ แล้วภาพหาย) | พิมพ์ว่าคิดว่าเป็นภาพอะไร |
| 2 | วาด | คำตอบของคนก่อนหน้าเท่านั้น | วาดตามนั้นบนกระดาษเปล่า |
| 3 | ทาย | ภาพนั้น (ดูได้ 10 วิ) | พิมพ์คำตอบอีกที |
| … | สลับไปจนครบทุกคน | | |

**จุดที่ห้ามแก้ผิด:** คนวาดต้องไม่เห็นภาพของรอบก่อน และคนทายต้องไม่เห็นข้อความใด ๆ
ความตลกของเกมมาจากการ "แปลภาพเป็นคำ แล้วแปลคำกลับเป็นภาพ" ซ้ำ ๆ ถ้าเห็นทั้งสองอย่างข้อมูลจะไม่เพี้ยนเลย
และการซ่อนภาพตอนพิมพ์ก็สำคัญ เพราะถ้าภาพยังอยู่ คนจะจ้องแล้วบรรยายละเอียดยิบจนภาพรอบถัดไปเหมือนเดิมเป๊ะ

โปรเจกต์นี้มีสองส่วน: **ตัวเกม** สำหรับผู้เล่น และ **หลังบ้าน** สำหรับผู้ดูแลระบบ

## เริ่มรัน

ต้องมี Node.js 20 ขึ้นไป

### 1. ยกฐานข้อมูลขึ้น

ถ้ามี Docker (แนะนำ — ง่ายที่สุด):

```bash
docker compose up -d
```

ถ้าไม่มี Docker ให้ติดตั้ง PostgreSQL 14+ เองแล้วสร้างฐานข้อมูลชื่อ `wadtor`

> ข้ามขั้นนี้ได้ถ้าแค่อยากลองเล่น — เกมทำงานได้โดยไม่ต้องมีฐานข้อมูล แค่จะไม่บันทึกอะไร
> และหน้าหลังบ้านจะใช้ไม่ได้

### 2. เซิร์ฟเวอร์

```bash
cd server
cp .env.example .env

# สร้างความลับสองตัว แล้วเอาไปใส่ JWT_SECRET กับ ADMIN_JWT_SECRET ใน .env (ต้องคนละค่า)
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"

npm install
npm run migrate         # สร้างตารางทั้งหมด
npm run create-admin    # สร้างบัญชีผู้ดูแลคนแรก (ถามชื่อผู้ใช้กับรหัสผ่าน)
npm run dev
```

### 3. หน้าเว็บ

```bash
cd client
npm install
npm run dev
```

- ตัวเกม: `http://localhost:5173`
- หลังบ้าน: `http://localhost:5173/admin.html`

ทดสอบหลายคนได้โดยเปิดหน้าต่างแบบไม่ระบุตัวตนเพิ่ม

## หลักการที่ยึดทั้งโปรเจกต์

**เซิร์ฟเวอร์เป็นเจ้าของความจริง** หน้าเว็บบอกเซิร์ฟเวอร์ได้แค่ "ฉันวาดเส้นพวกนี้" เท่านั้น
เวลา รอบ ของแถม การจับคู่สาย ตัดสินที่เซิร์ฟเวอร์ทั้งหมด

**การสุ่มอยู่ที่เซิร์ฟเวอร์** ถ้าสุ่มของแถมที่เบราว์เซอร์ ผู้เล่นเปิดเครื่องมือนักพัฒนาแล้วปิดของแถมตัวเองได้ใน 10 วินาที

**เก็บภาพเป็นเส้น ไม่ใช่ไฟล์รูป** ทำให้ยางลบผีและสีเพี้ยนเป็นแค่การแก้ตัวเลข
และภาพหนึ่งใบมีขนาดราว 5–30 KB แทนที่จะเป็น PNG หลายร้อย KB

**ฐานข้อมูลล่มแล้วเกมต้องไม่ล่ม** การบันทึกทำแบบไม่บล็อก ถ้าเขียนไม่สำเร็จจะ log ไว้แล้วเล่นต่อ
ทดสอบแล้วทั้งสามกรณี: ฐานข้อมูลปกติ / ฐานข้อมูลล่มกลางเกม / ไม่มีฐานข้อมูลเลย

**ของแถมเป็นปลั๊กอิน** เพิ่มตัวใหม่ = เพิ่ม object หนึ่งก้อนใน `challenges.js` แล้วต่อ mapping อีกบรรทัดใน `DrawRound.jsx`
โดยระบุ `scope` ว่าใช้กับรอบไหน: `drawer` = รอบวาด, `handoff`/`viewer` = รอบทาย
เซิร์ฟเวอร์กรองให้เองว่าของแถมตัวไหนออกได้ในรอบไหน จึงไม่มีทางเจอ "ห้ามยกมือ" ในรอบที่ไม่ได้วาด

## หน้าหลังบ้านทำอะไรได้

| หน้า | ใช้ทำอะไร |
|---|---|
| **ภาพรวม** | ห้องที่เปิดอยู่ตอนนี้ ผู้เล่นออนไลน์ สถิติสะสม และการกระจายของคำใบ้ (ใช้ตรวจว่าถุงสุ่มทำงานถูก) |
| **คิวรายงาน** | เห็นภาพที่ถูกรายงานจริง ๆ แล้วเลือก: ปิดเรื่อง / ลบภาพ / ลบภาพแล้วแบน 7 วัน ทุกครั้งต้องใส่เหตุผล |
| **คลังผลงาน** | เปิดดูเกมย้อนหลังทีละสาย เห็นคำใบ้ตั้งต้น ทุกขั้น และของแถมที่ออกในแต่ละรอบ ลบภาพรายใบได้ |
| **แบนและบันทึก** | รายการแบนที่ยังมีผล จัดการบัญชีผู้ดูแล และบันทึกทุกการกระทำของผู้ดูแล |

**บทบาทมีสองระดับ**

- `moderator` — ตรวจรายงาน ลบภาพ ดูทุกอย่างได้
- `owner` — ทำได้ทุกอย่างของ moderator บวกกับแบนผู้เล่น ยกเลิกแบน ปิดห้อง และสร้างบัญชีผู้ดูแล

แยกสองระดับเพราะการแบนกระทบกว้างกว่าและย้อนกลับยากกว่าการลบภาพหนึ่งใบ

## รายการความปลอดภัยที่ทำแล้ว

**ฝั่งผู้เล่น**

- ตรวจตั๋ว JWT ตอน handshake ของ socket ไม่ใช่ตอนเรียก event
- `playerId` ออกโดยเซิร์ฟเวอร์เท่านั้น หน้าเว็บกำหนดเองไม่ได้
- ตรวจ payload ทุก event ด้วย zod ก่อนแตะตรรกะเกม
- จำกัดอัตราส่ง event ต่อ socket (ถังโทเคน 25/วินาที) และจำกัด REST 60 ครั้ง/นาที/IP
- เพดานขนาดข้อมูล: 300 เส้น, 5,000 จุด, `maxHttpBufferSize` 512 KB
- ตรวจสิทธิ์ทุกคำสั่ง — เจ้าของห้องเท่านั้นที่เริ่มเกม แก้กติกา เตะคน เลื่อนหน้าเฉลย
- ตรวจซ้ำว่าผลงานเป็นไปตามของแถมจริง ไม่เชื่อหน้าเว็บ
- รายงานผลงานตัวเองไม่ได้ และรายงานภาพเดิมซ้ำไม่ได้
- ตรวจรายการแบนทั้งตอนขอตั๋วและตอนเชื่อมต่อ socket
- รหัสห้องสุ่มจาก `crypto.randomBytes` ไล่เดาไม่ได้
- ล้างอักขระควบคุมและอักขระซ่อนตัวออกจากชื่อเล่นและแชท

**ฝั่งหลังบ้าน**

- รหัสผ่านแฮชด้วย scrypt (ไม่ใช่ MD5/SHA เปล่า) และเทียบแบบเวลาคงที่
- ล็อกบัญชีอัตโนมัติ 15 นาที หลังกรอกผิด 5 ครั้ง และจำกัดล็อกอิน 8 ครั้ง/15 นาที/IP
- ข้อความตอบตอนล็อกอินผิดเหมือนกันหมด ไล่เดาไม่ได้ว่าบัญชีไหนมีอยู่จริง
- เซสชันอยู่ในคุกกี้ `httpOnly` + `Secure` + `SameSite=strict` ขอบเขตจำกัดที่ `/api/admin`
- ตั๋วแอดมินใช้ความลับคนละตัวกับตั๋วผู้เล่น และเซิร์ฟเวอร์ปฏิเสธการสตาร์ตถ้าตั้งซ้ำกัน
- ด่านกัน CSRF สองชั้น: `SameSite=strict` + บังคับ header `X-Admin-Request`
- สิทธิ์แยกตามบทบาท ตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ
- ทุกการกระทำถูกบันทึกใน `audit_log` ซึ่งไม่มีคำสั่งลบหรือแก้
- ภาพที่ถูกลบจะถูกล้างข้อมูลจริงในฐานข้อมูล และเซิร์ฟเวอร์ไม่ส่งออกไปอีกแม้ในหน้าแอดมิน
- ไม่มีบัญชีเริ่มต้นแบบ admin/admin ในระบบ ต้องสร้างเองผ่าน CLI
- หน้าหลังบ้านบิลด์เป็นไฟล์แยก โค้ดแอดมินไม่ถูกส่งไปที่เบราว์เซอร์ผู้เล่นทั่วไป

**ทั่วไป**

- ใช้ parameterized query ($1, $2) ทุกที่ ไม่ต่อสตริง SQL เอง
- เก็บ IP เป็นค่าแฮชพร้อมเกลือ ไม่เก็บ IP ตรง ๆ (ตาม PDPA)
- helmet + CSP + CORS รายชื่อขาว + บังคับ websocket อย่างเดียว
- ไม่ส่ง stack trace กลับไปหาผู้ใช้
- `.env` อยู่ใน `.gitignore` และเซิร์ฟเวอร์ล้มทันทีถ้าตั้งค่าไม่ครบในโหมด production

## ที่ยังไม่ได้ทำ

| งาน | ความสำคัญ | หมายเหตุ |
|---|---|---|
| ประกาศความเป็นส่วนตัว + ปุ่มขอลบข้อมูล | สูง | จำเป็นตาม PDPA ถ้าเปิดให้คนทั่วไปเล่น ตอนนี้ยังไม่มีหน้านี้ |
| งานลบข้อมูลเก่าอัตโนมัติ | สูง | ควรลบภาพห้องสาธารณะที่เก่ากว่า 30 วันทิ้ง |
| Turnstile/hCaptcha ตอนหาห้องสาธารณะ | กลาง | กันบอทถล่มห้อง |
| Redis + socket.io adapter | กลาง | จำเป็นเมื่อรันหลายเครื่อง และต้องย้าย `promptPool` ไปด้วย |
| ระบบสมาชิก (OAuth) | ต่ำ | โครงตั๋วรองรับอยู่แล้ว เพิ่ม endpoint ใหม่ได้เลย |
| ส่งออกเป็น GIF หรือวิดีโอ | ต่ำ | ข้อมูลเป็นเส้นอยู่แล้ว ทำ time-lapse ได้ไม่ยาก |
| แชทในห้อง (หน้าจอ) | ต่ำ | ฝั่งเซิร์ฟเวอร์ทำเสร็จแล้ว เหลือแค่ UI |
